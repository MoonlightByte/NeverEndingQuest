# Issue #159 — model-authored areaConnectivity/areaConnectivityId pollution

## Root cause
`areaConnectivity` (destination area NAMES) and `areaConnectivityId` (destination LOCATION IDs, parallel
by index) are code-owned cross-area fields. Story-first owns them: `compile_area_binding` writes the
compiled links into the trusted stub (`compilers.py:239-283,325-347`), and story-first then VALIDATES
exact stub equality (raises on mismatch) via `TRUSTED_LOCATION_FIELDS` (`validators.py:844-853`) in
`validate_story_first_location_result` (`:1095-1111`). Legacy is polluted because (1) the T026
prompt+schema instruct the model to author them AND mislabel `areaConnectivityId` as "area IDs"
(`location_generator.py:930-944,1248-1253`; `loca_generation_schema.json:94-103`; `loca_schema.json:93-102`;
`locationfile_schema_strict.json:100-108`), (2) `_canonicalize_t026_stub_owned_fields` restores
locationId/coordinates/dangerLevel but NOT these two arrays (`location_generator.py:133-162`), and (3)
the classic finalizer APPENDS code links without clearing model ones (`module_builder.py:2243-2264`) —
so both survive (`WB001:A03 -> ['WW001','B01']`, `WW001` an area ID in a location-ID slot).

## 159-A — trusted stub authoritative at the T026 boundary (`location_generator.py`)
In `_canonicalize_t026_stub_owned_fields`, after the existing whole-batch ordered-ID preflight succeeds
(`:110-131`), deep-copy `areaConnectivity` and `areaConnectivityId` from the corresponding trusted stub
into every returned location, on every attempt (same pattern as the Item D coordinate restore at
`:141-162`; applies across all three T026 routes at `:1374-1384,1398-1407,1535-1545`). Legacy stubs are
empty (`area_generator.py:594-613`) -> arrays become `[]`; story-first stubs carry compiled links ->
preserved exactly in order/multiplicity, which makes the downstream exact-equality validator pass by
construction (NOT weakened). Add a small stub-shape validator (both fields equal-length string lists,
no blanks; do not infer/repair pairings). Keep the existing behavior that a present-but-conflicting ID
or suspect order returns the untouched model response. One bounded advisory count when values differed;
never log model prose.

## 159-C — classic finalizer is the sole author, from a shared nextPoints-aware extractor
(`module_builder.py`; shared extractor placed for reuse by the Step 4.56 detector)
1. **Shared expected-edge extractor.** Do NOT reuse `_plot_ordered_area_transitions` as-is — it walks
   adjacent `plotPoints` order only and ignores `nextPoints` (`:2283-2304`), while the detector
   separately adds `nextPoints` edges (`validators.py:1504-1532`). Introduce ONE shared extractor used
   in BOTH the finalizer and `validate_plot_route_agreement`, so they agree by construction.
   **Fallback trigger (precise).** T028 REQUIRES `nextPoints` on every plot point but permits all
   arrays to be empty (`module_builder.py:261-335`), so `nextPoints` is authoritative whenever any
   usable cross-area edge exists in the nextPoints graph; the adjacency (plotPoints-order) fallback
   fires ONLY when `nextPoints` yields NO usable cross-area graph edges (legacy/degenerate plots).
   Do NOT union adjacency with a valid branched nextPoints graph — that invents sibling edges. Ideally
   validate T028 cross-area reachability BEFORE finalization; an all-empty nextPoints graph can pass

3. **Validate before any write:** equal-length parallel arrays; unique pairs; each target resolves to
   exactly one location in another area; paired name == target area name; exact reciprocal pair at the
   expected endpoint; link set == extractor-derived set (no model extras); local `connectivity`
   unchanged.
4. **Honest crash semantics.** Per-area `_atomic_save_json` (`:2347-2351`) is NOT multi-file
   graph-atomic. Do not claim cross-file atomicity. The safety model is: validate the full staged graph
   in memory FIRST; only if all invariants pass, write the areas; a crash mid-write is recovered by the
   unpublished managed-candidate lifecycle (a failed candidate is aborted/not published), and the
   finalizer is idempotent on rerun (clear-then-rebuild reproduces the same graph). A durable multi-file
   journal is out of v1 scope.
5. Classic-only in the actual call flow (classic finalizes at `module_builder.py:503-520`; story-first
