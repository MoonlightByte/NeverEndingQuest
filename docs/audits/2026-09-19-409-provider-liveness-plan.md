## 2. Root cause (code-proven, file:line on 94611b9a)

1. **No phase evidence leaves the child.** `_child_main` (`live_provider_call.py:820-856`) reads stdin, redirects its own stdout/stderr to devnull (`:830-832`), calls `api_client.create_completion` and writes exactly one pickle at the end. The parent spawns it with `stderr=subprocess.DEVNULL` (`:1170-1174`) and waits with `process.communicate(timeout=0.25)` (`:1262`). A generation reaped at the backstop leaves the master log with `httpStatus=null, causeClass=""` (`api_logger.py:68-115`) and nobody can say whether it died connecting, sending, waiting for headers, or mid-body. This is why #409, #348 and #398 each blame a different stage.
2. **The pipe defect (#409 original) is fixed and is not the recurrence.** d3c4cbf9 feeds stdin from a writer thread (`:1217-1241`). The T042 stall carried 3,260 bytes, under the 64 KiB pipe buffer, so partial writes cannot apply.
3. **#428 is real but cannot produce a 600 s wait.** `_feed_request` (`:1231-1240`) closes over `request_stdin`, a local rebound each generation, and is never joined. An old writer that wakes late closes the new child's stdin; the new child reads a truncated payload, `pickle.loads` raises, `_primitive_error` returns a deterministic envelope with empty correlation, correlation is rejected, and the parent synthesizes `ProviderChildUnavailable` and reissues after the backoff (`_delay_for_error`, 0.5-8 s). A fast spurious reissue, never a stall.
4. **Chat Completions gives no liveness during reasoning, streamed or not.** Measured on real requests (`results.ndjson`): with `stream=True` the response headers arrive together with the first output token: 1.5 s at effort none, 3.4 s at low, 6.7 s at forced high, with the connection silent throughout reasoning. Any header-wait cutoff on this endpoint is exactly the arbitrary timer the clarification bans.
5. **The Responses endpoint does give the signal.** Streamed, `response.created` arrives 0.72-0.86 s after the request is sent on every size tried (3 KB to 133 KB, effort none to high), `response.in_progress` follows within 1 ms, a reasoning `output_item.added` arrives ~0.25 s later and `output_item.done` when thinking ends, then text deltas every few ms. json_object formatting, temperature at effort none and prompt caching (cache_write_tokens 19,691 on T096) all work (`results-responses.ndjson`).
6. **A silently dropped TCP path is invisible for longer than the backstop.** Kernel defaults here: `tcp_keepalive_time 7200`, `tcp_retries2 15`. A read that waits on a path the NAT/vSwitch dropped never errors inside ten minutes. Keepalive socket options attach through `httpx.HTTPTransport(socket_options=...)` and the call succeeds (probe, keepalive=true). This WSL runs `networkingMode=mirrored` (`/mnt/c/Users/david/.wslconfig`); Microsoft WSL issues #11369, #13459, #41102 and moby #48201 report mirrored-mode TCP stalls and silent drops. Suspect for the WSL recurrence, unproven, and irrelevant to the native-Windows reports, which is why detection must not depend on the cause.
7. Fresh-process storm (81 plain T042 calls, each a new process, TCP and TLS): 0 stalls, max 5.0 s. The failure is rare (about 1 in 300 game calls across sessions) and cannot be reproduced on demand; the plan therefore makes every future occurrence self-describing instead of chasing a repro.

## 3. Goal and player promise

Every provider call tells the truth about where it is (connecting, delivered, acknowledged, working, receiving, done), a dead connection is noticed in seconds and reissued through the existing loop, real provider progress replaces the local stopwatch as the liveness signal, and every stall that still happens names its phase in the master log. Advances p10 ACKNOWLEDGMENT & PACING (honest progress on >10 s operations, #96) and p11 NEQ-PROVIDER-01/02. Must not degrade: exact-once turn commits, supersession by Load/Reset/Quit, the validation boundary (no partial or rejected text reaches the player), per-turn token cost, Legacy/LM Studio/Gemini providers.

## 5. Approaches considered

- **A. Shorter backstop** (e.g., 60 s). Rejected: banned by the clarification; kills legitimately long reasoning; still blind.
- **B. Chat Completions streaming only.** Rejected as the liveness signal: measured silent until the first token at every effort; keeps the blind wait during reasoning. Retained for legacy/lmstudio where it is the only endpoint and where local models stream tokens (and reasoning_content) as they generate.
- **C. Responses endpoint streaming + phase ledger + TCP keepalive + writer fix (chosen).** Every observable class is recovered at its own trigger; the unobservable class (socket alive, provider never acknowledges) is named honestly and left to D-409-2.
- **D. Background Responses with server-side polling / resumption.** Not proposed: changes retention and lifecycle, owner paused it in #398; may be revisited if D-409-2 data shows the unobservable class is common.
- **E. Reissue racing (fire a second request while the first is silent).** Rejected: duplicates billing and violates exactly-once discipline.
