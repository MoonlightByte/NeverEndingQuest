# Multi-Model Capture Validation System - Design Document

**Date:** 2026-02-22
**Status:** Approved
**Approach:** Agent-Generated Validator Library

---

## Executive Summary

This document describes the design for an automated validation system that analyzes multi-model capture data from 95 API callsites (T001-T095). The system uses agents to discover validation requirements once, then generates deterministic Python validators for fast, repeatable validation of all captured model outputs.

**Key Benefits:**
- Deterministic, non-AI validation (pure Python code)
- Fast execution (validates hundreds of captures in seconds)
- Comprehensive analysis (JSON structure, schema compliance, business rules, baseline comparison)
- Drill-down capability (high-level summary + detailed per-task reports)

---

## System Architecture

### Two-Phase Design

**Phase 1: Discovery (One-Time Setup)**
- Dispatch 95 parallel agents (one per API callsite)
- Each agent analyzes callsite from all three sources:
  1. System prompts (expected schema)
  2. Callsite code (how response is used)
  3. Existing validators (validation rules)
- Agent generates standalone validator module
- Output: `validators/task_T001.py` through `validators/task_T095.py`

**Phase 2: Analysis (On-Demand)**
- Single script imports all 95 validators
- Loops through all capture files in `model_captures/`
- Runs deterministic validation on each captured output
- Produces aggregated summary + detailed per-task reports

### Component Structure

```
model_captures/               # Input: Captured API outputs
├── T001.json
├── T079.json
└── ...

validators/                   # Generated: Deterministic validation code
├── __init__.py
├── task_T001.py             # Validator for T001
├── task_T079.py             # Validator for T079
└── ...

reports/                      # Output: Validation results
├── validation_summary.html  # High-level overview
├── validation_summary.json  # Machine-readable summary
└── details/
    ├── T001_validation.json # Detailed results per task
    ├── T079_validation.json
    └── ...

tools/
├── discover_validators.py   # Phase 1: Generate validators
└── analyze_captures.py      # Phase 2: Run validation
```

### Data Flow

```
1. Discovery Phase (one-time):
   docs/audit/...json → discover_validators.py → [95 agents] → validators/*.py

2. Analysis Phase (on-demand):
   model_captures/*.json → analyze_captures.py → validators/*.py → reports/*
```

## Validator Module Structure

For each task (e.g., T079), the agent reads:

1. **System prompt** from capture → Extract expected JSON schema/structure

3. **Existing validators** (if referenced) → Extract validation rules
4. **Response format patterns** from recent captures → Identify common structures

### Validation Levels

Each validator performs multiple checks:

1. **JSON parsing** - Can the output be parsed as JSON?
2. **Schema structure** - Does it have required fields with correct types?
3. **Business rules** - Do values make logical sense? (e.g., gold decreased by 1)
4. **Baseline comparison** - Does it produce functionally equivalent results to baseline?
5. **Format violations** - Extra text, markdown code blocks, narrative additions?

## Discovery Phase Design

### Execution Flow (discover_validators.py)

```python
# 1. Load API call inventory
inventory = load_json("docs/audit/2026-02-12-openai-api-call-inventory.json")
# → 95 tasks with path, line, task_id, scope

# 2. Dispatch 95 agents in parallel (using Task tool)
for task in inventory:
    Task(
        subagent_type="general-purpose",
        description=f"Generate validator for {task['task_id']}",
        prompt=f"""
        Analyze API callsite and generate validator module:

        Task ID: {task['task_id']}
        File: {task['path']}
        Line: {task['line']}

        Steps:
        1. Read the file at {task['path']} around line {task['line']}
        2. Find system prompt in recent captures (model_captures/{task['task_id']}.json)
        3. Search for related validators in core/validation/
        4. Extract:
           - Expected JSON schema from system prompt
           - Validation rules from code/validators
           - Business logic from callsite usage
        5. Generate validators/task_{task['task_id']}.py with all validation functions

        Output: Write the complete validator module to file.
        """
    )

# 3. Wait for all agents to complete
# 4. Validate generated validators (import test)
# 5. Generate validators/__init__.py to export all validators
```

### Agent Task Breakdown

Each agent will:

1. **Read callsite code** (~50 lines around the API call)
2. **Read capture file** (find most recent entry for system prompt)
3. **Search for validators** (grep for related validation code)
4. **Extract schema** from system prompt (look for JSON examples, structure descriptions)
5. **Generate validator** using the template structure
6. **Write file** to `validators/task_TXXX.py`

### Parallel Execution

- All 95 agents run concurrently
- Each agent is independent (no shared state)
- Expected runtime: ~5-10 minutes for all 95 validators
- Progress tracking: Show completed count (e.g., "45/95 validators generated")

### Error Handling

- If agent fails to generate validator → Create stub validator with basic JSON parsing
- Log failures to `discovery_errors.log`
- Allow partial success (some validators generated, some failed)

## Analysis Phase Design

### Execution Flow (analyze_captures.py)

```python
# 1. Discover all capture files
capture_files = glob("model_captures/T*.json")
# → [T001.json, T002.json, ..., T095.json]

# 2. Import all validators
from validators import task_T001, task_T002, ..., task_T095

# 3. For each capture file:
for capture_file in capture_files:
    task_id = extract_task_id(capture_file)  # "T079"
    validator = get_validator(task_id)  # task_T079 module

    # Load all capture entries
    captures = load_json(capture_file)  # May have multiple entries

    # 4. Validate each capture entry
    for entry in captures:
        baseline_output = entry["outputs"]["gpt-4.1-...|baseline"]["content"]

        # Validate baseline first
        baseline_result = validator.validate_output(baseline_output, entry["input"])

        # Validate each variant against baseline
        for variant_label, variant_data in entry["outputs"].items():
            if variant_label == baseline:
                continue

            result = validator.validate_output(
                variant_data["content"],
                entry["input"],
                baseline_output=baseline_output
            )

            # Store results
            store_result(task_id, entry["timestamp"], variant_label, result)

# 5. Aggregate results and generate reports
generate_summary_report()
generate_detailed_reports()
```

## Error Handling & Edge Cases

### Handling Missing Validators

**Scenario:** Capture exists for T042, but no validator was generated.

**Solution:**
- analyze_captures.py detects missing validator
- Falls back to generic JSON validation (parsing only)
- Reports warning: "T042: No validator found, using generic validation"
- Still produces results (limited to JSON parse check)

### Handling Malformed Captures

**Scenario:** T079.json is corrupted or has invalid structure.

**Solution:**
- Catch JSON parse errors when loading capture file
- Log error: "T079: Capture file malformed, skipping"
- Continue processing other tasks
- Report in summary: "12 tasks processed, 1 skipped (malformed)"

### Handling Variant Errors in Captures

**Scenario:** Capture has `"errors": {"gpt-5.2|none": "KeyError: 'provider'"}` instead of output.

**Solution:**
- Validator skips variants with errors (no output to validate)
- Report shows: "gpt-5.2|none: API ERROR (not validated)"
- Summary counts: "658 outputs validated, 42 API errors skipped"

### Handling Schema Evolution

**Scenario:** API callsite changes after validators are generated.

**Solution:**
- analyze_captures.py detects validation failures spike
- User re-runs: `python discover_validators.py --task T079`
- Regenerates single validator for updated callsite
- Validation resumes with new schema

### Handling Empty Captures

**Scenario:** T015.json exists but has no capture entries yet.

**Solution:**
- Validator detects empty capture list
- Reports: "T015: No captures to validate"
- Summary shows: "11/12 tasks had data"

### Graceful Degradation

If validator crashes during validation:
```python
try:
    result = validator.validate_output(...)
except Exception as e:
    result = {
        "valid": False,
        "errors": [f"Validator crashed: {str(e)}"],
        "checks": {"validator_error": True}
    }
```

### Re-running Discovery for Specific Tasks

```bash
# Regenerate all validators
python discover_validators.py

# Regenerate specific task(s)
python discover_validators.py --tasks T079,T082,T067

# Regenerate failed validators from last run
python discover_validators.py --retry-failed
```

## Implementation Considerations

### Dependencies

- Python 3.10+
- No additional packages required for validators (pure Python)
- `jsonschema` library (optional, for advanced schema validation)
- HTML templating for summary report (e.g., Jinja2)

### File Organization

```
/mnt/c/dungeon_master_v1_testing/
├── tools/
│   ├── discover_validators.py     # Phase 1 script
│   └── analyze_captures.py        # Phase 2 script
├── validators/
│   ├── __init__.py
│   ├── task_T001.py
│   └── ... (95 validator modules)
├── reports/
│   ├── validation_summary.html
│   ├── validation_summary.json
│   └── details/
│       └── ... (per-task JSON reports)
└── model_captures/
    └── ... (existing capture files)
```

### Testing Strategy

1. **Validator Generation Test**: Run discovery on known callsite (T079), verify generated code
2. **Validation Test**: Run analysis on known-good capture, verify pass
3. **Failure Detection Test**: Run analysis on known-bad capture (like gemini-3-flash|high), verify failure caught
4. **Edge Case Tests**: Empty captures, missing validators, malformed JSON

## Conclusion

This design provides a comprehensive, automated validation system for multi-model capture data. By using agents to discover validation requirements once, then generating deterministic Python validators, the system achieves:

- **Speed**: Instant validation (no API calls)
- **Accuracy**: Thorough validation (JSON, schema, business rules, baseline comparison)
- **Usability**: High-level summary + detailed drill-down
- **Maintainability**: Re-generate validators when APIs change

The two-phase approach (discovery + analysis) balances initial setup time with ongoing validation performance, making it practical for continuous multi-model testing workflows.
