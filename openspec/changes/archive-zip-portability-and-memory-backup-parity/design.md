## Context

The current save system writes directory snapshots that are portable by manual copy, but archive saves do not automatically produce a single-file backup artifact. For library and public-service tabletop sessions, operators need a deterministic zip generated by the existing GUI Archive save flow, so backups can be copied to external media without extra UI actions. At the same time, memory parity has been implemented for save/restore, but nuclear reset backup does not explicitly guarantee memory state inclusion.

Constraints:
- Keep archive zip behavior tied to existing save dialog mode selection and avoid new GUI controls.
- Reuse existing memory package validation/import/export helpers where possible.
- Preserve existing save folder format and restore semantics.

Stakeholders:
- Operators moving campaigns between devices.
- Facilitators who need low-friction backup/restore in live tabletop settings.
- Maintainers responsible for merge-safe upstream integration.

## Goals / Non-Goals

**Goals:**
- Auto-generate portable zip artifact whenever `Archive Edition` (`save_mode=full`) is triggered from existing GUI save action.
- Ensure archive zip captures campaign state recoverable across all played modules, including memory package artifacts.
- Surface zip artifact status/path in existing save response payload.
- Add explicit memory-state capture in nuclear reset backup phase.

**Non-Goals:**
- Build cloud sync or remote storage integration.
- Change save lineage/worldline generation behavior.
- Introduce new persistence backend beyond existing filesystem and memory DB package format.

## Decisions

### 1) Zip payload is a full save-folder envelope
Decision: archive zip contains one top-level campaign archive envelope with existing save-format artifacts and campaign-wide recovery data for played modules (`save_metadata.json`, gameplay snapshots, optional `memory_db_package/`).

Rationale:
- Matches current restore assumptions.
- Keeps archive payload deterministic for operator backup copy-to-USB flow.

Alternatives considered:
- Flatten archive with custom manifest-only layout: rejected due to extra conversion complexity.

### 2) Archive zip generation is triggered only by full save mode
Decision: backend auto-generates zip only when save mode is `full`; `essential` save mode remains unchanged.

Rationale:
- Aligns with operator intent: "Archive Edition" equals portable backup artifact.
- Avoids adding new GUI controls while preserving current UX.

Alternatives considered:
- Separate export button/action: rejected per workflow requirement to avoid additional GUI controls.

### 3) Archive save fails closed if required zip artifact cannot be produced
Decision: when `save_mode=full`, save operation returns failure unless zip generation succeeds.

Rationale:
- Portable backups are mandatory in operator environment; silent non-zip success is unacceptable.

Alternatives considered:
- Mark save success even if zip fails: rejected because it violates portability requirement.

### 4) Reset backup captures memory state explicitly
Decision: update reset backup phase to include memory state artifact (`data/memory.db` if present, or equivalent packaged artifact).

Rationale:
- Aligns reset backup with save/restore memory parity goals.

Alternatives considered:
- Leave reset backup unchanged: rejected because it creates parity gaps during operator rollback workflows.

## Risks / Trade-offs

- [Large archive zips can increase save latency] -> Mitigation: bounded zip scope rules and clear status messaging in save result.
- [Campaign-wide archive scope ambiguity could omit needed data] -> Mitigation: define "played modules" source-of-truth in implementation (for example campaign summaries/archives or registry references) and test against multi-module sessions.
- [Fail-closed archive policy increases save failures under storage pressure] -> Mitigation: explicit error reporting and recommendation to retry after freeing disk space.
- [Reset backup parity changes may increase backup size] -> Mitigation: include memory artifact once and document expected size overhead.

## Migration Plan

1. Add backend zip generation helper and archive mode trigger wiring in `updates/save_game_manager.py`.
2. Define and implement campaign-wide archive inclusion rules for "all played modules."
3. Add save response metadata/status so existing GUI flow can surface zip artifact path.
4. Add reset backup memory-state capture in `utils/reset_campaign.py`.
5. Verify:
   - `python3 -m py_compile updates/save_game_manager.py web/web_interface.py utils/reset_campaign.py`
   - Archive Edition save produces zip artifact and returns path
   - forced zip failure causes archive save failure
   - multi-module campaign archive contains required module data + memory artifact.

Rollback strategy:
- Disable full-mode auto-zip path and keep existing folder save path operational.
- Revert reset backup memory capture step if regression appears, while preserving existing backup behavior.
