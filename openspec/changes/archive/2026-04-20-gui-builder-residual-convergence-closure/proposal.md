## Why

The readiness convergence hardening slice succeeded in making residual failures observable, but the Numillian canary still fails on four concrete structural blocker classes. The next change is needed to close those validator-driven gaps so the uploader can move from reporting residual debt to actually resolving it when safe.

## What Changes

- Add validator-driven residual closure for unresolved monster references instead of relying only on authored hydration candidates.
- Extend monster schema completion so existing monster files can be repaired from authoritative source data when available and classified cleanly when not.
- Make finale prerequisite repair operate against the live `module_plot.json` shapes emitted by current toolkit modules.
- Strengthen spatial contradiction remediation so unchanged contradictions are either converged or explicitly escalated as author-required structural debt.
- Persist residual-closure canary artifacts showing whether Numillian advances beyond the current schema-era blocker set.

## Capabilities

### New Capabilities
- `toolkit-residual-convergence-closure`: Closes validator-driven residual readiness blockers after convergence instrumentation has already classified them.

### Modified Capabilities
- `homebrew-ingest-monster-materialization`: materialization and downstream repair must support authoritative schema completion and validator-derived reference closure.
- `tt-monster-reference-integrity-validation`: unresolved reference outputs must remain deterministic and consumable by residual closure repair paths.
- `module-plot-progression-path-validation`: finale prerequisite repair must align with live plot payload shapes while preserving fail-closed ambiguity handling.
- `tt-spatial-coordinate-resolution`: remediation must either resolve repeated adjacency contradictions or classify them as structural author debt.
- `module-publishability-reporting`: reporting must expose residual-closure outcomes clearly enough to distinguish repaired progress from unresolved structural debt.

## Impact

- Affected code: `web/extensions/toolkit_homebrew_readiness_gate.py`, validator/remediation helpers, and readiness/canary report generation.
- Affected systems: toolkit readiness repair loop, monster/reference remediation, plot/spatial remediation, and report artifacts under `docs/operations/`.
- Merge safety: SHOULD remain concentrated in toolkit/remediation extensions and scripts, with no upstream gameplay-path rewrites.
- SP/MP compatibility: MUST remain neutral; this work only changes authoring/readiness repair workflows, not runtime single-player or tabletop gameplay behavior.
